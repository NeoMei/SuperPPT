# SuperPPT

SuperPPT 把主题描述、粘贴文本或 Markdown 拆解为经过确认的高细节、图文并茂的图片优先演示文稿，并允许将指定页面的可靠对象转换为可编辑单页后替换回整套 PPTX。它不是整套全可编辑方案。

## 工作流

1. 保留原始输入，将描述、粘贴文本或 Markdown 生成内容简报。
2. 展示整套页面大纲，等待第一个普通确认。
3. 展示逐页核心观点、文字、视觉主体、构图和关系，等待第二个普通确认。
4. 从紧凑风格库中单选一个风格，生成真实代表页样张，等待第三个普通确认。
5. 用提示词编译器生成有前景、中景、背景、材质、光线、空间关系和微细节的页面，完成 QA 后组装。

整个流程恰好 3 个普通确认：大纲、逐页描述和风格样张。已确认的前序内容仍可修改；SuperPPT 会先显示受影响的稳定页面 ID 和导出，再局部失效、重新确认并生成新版本，老版本仍可回滚。

## 风格与修改

内置 10 种真实 16:9 高细节预览，风格只能单选。文字和可靠提取的透明素材可进入 editable 路由；主插画、背景、整体布局、信息结构或 manifest 中不存在的目标进入 regenerate 路由。首次转换前，页面统一为精确的 1280×720 PNG，这是转换器边界。

## 输出与可编辑边界

交付 PPTX、PDF、蒙太奇、项目状态、规划文件、风格配方和验收记录。普通页面是整页图片；只有用户选中的页面中，经 `image-to-editable-pptx` 成功提取并替换的文字或可靠透明素材才可编辑。未成功提取的对象仍属于背景像素，不是真实可编辑对象，所以它不是整套全可编辑。

产物生成和自动化测试不等于完成验收。真实 WPS 或 PowerPoint 客户端验收必须先运行 `acceptance-smoke-copy --project <path>`，再在生成的受控副本中编辑代表性文字或已提取素材，保存、关闭并重新打开；禁止直接保存改写 canonical `deck.pptx`。`acceptance-record` 只接受与当前项目 revision、canonical 源 SHA、受控副本 descriptor 和保存后副本 SHA 一致的证据。

## 依赖与隐私

`ai-image-to-ppt` 和兼容版 `image-to-editable-pptx` 是外部依赖，不随 SuperPPT 捆绑或静默安装。`npm run cli -- preflight` 会验证来源、版本和能力。模型调用前会披露提供者、页数、最大调用次数、出站文本/参考图和输出位置。API 密钥只通过环境传给子进程；提示词和评审输入使用私有临时文件，日志只保留必要哈希。

## 本地开发

SuperPPT 需要 Node.js 22.6 或更高版本。

```bash
npm ci
bash scripts/verify.sh
```

## 安装

当前未进行仓库发布或全局安装，本地开发状态不代表发布状态。当仓库获得独立的发布授权后，Git-backed marketplace 来源将为 `https://github.com/NeoMei/SuperPPT.git`，主分支为 `main`。

## V1 限制

只接收描述、粘贴文本和 Markdown；不直接摄取 DOCX、PDF 或现有 PPTX。可编辑重建取决于转换器的实际提取结果，复杂场景会回退为单页重新生成。
