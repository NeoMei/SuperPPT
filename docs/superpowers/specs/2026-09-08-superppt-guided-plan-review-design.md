# SuperPPT 按需问答与可视化方案确认

日期：2026-09-08。

状态：用户已确认方向，并在具体设计稿交付后再次确认（2026-09-08）；设计已定稿，尚未实现。[实施计划](../plans/2026-09-08-superppt-guided-plan-review.md)已拆分任务和验收步骤。

## 1. 要解决的问题

现有 SuperPPT 已有内容方案与选款、样页、完整 PPTX 三个决策点。规划指引要求仅追问重要缺失事实，但没有明确何时追问、如何推荐及怎样复用答案。方案正文一次展开完整逐页内容，较长方案不便定位修改。现有 HTML 主要用于选风格，无法在同一处核对内容、样页与生成预算。

本次吸收 brainstorming 的逐题澄清、方案比较和可视化沟通方式，使生成前的方案更容易理解和修改。完整素材不强制经过访谈；内容、大纲、风格不分别新增审批门。

## 2. 用户流程

读取材料 → 必要时逐题澄清 → 展示完整方案并修改 → 确认方案并生成样页 → 确认样页并生成整套 → 回看完整 PPTX 并确认交付。

问答属于规划工作，浏览方案中的不同区块属于同一个 plan-review。正常流程仍是三个业务决策点，不把对话条数限制为三条，也不为机器工作新增「继续」确认。

## 3. 按需问答

### 3.1 何时问

Agent 先读取用户输入、源材料和已有回答，再判断尚缺信息是否会显著改变叙事、内容取舍、页数或交付范围。

| 输入情况 | 默认行为 |
| --- | --- |
| 完整文稿且目标明确 | 直接出方案；已有事实不重问 |
| 只有主题或少量线索 | 按影响程度逐题澄清受众、目标、必须包含的内容及必要约束 |
| 存在两种以上有实质差异的讲述方向 | 给出两三个内容组织方案、适用条件与推荐理由，再由用户选择 |
| 只缺可逆且影响较小的偏好 | 采用合理默认值，在方案中列出关键假设供修改 |
| 缺少必须准确的数字、结论或承诺 | 明确缺口并追问，不能把假设写成源材料事实 |

不按固定题单轮询所有字段，不强制每个任务比较多套方案。保留用户已批准的源结构和完整文案；用户未授权重构时，不借方案比较自行删减或改变叙事。

### 3.2 怎样问

每次聚焦一个问题，简短说明它影响什么。适合选择题时提供两三个选项，推荐项在前并附一句理由；始终允许用户自由回答或自行补充多个问题的答案。

例如：

> 这次汇报希望听众最后做什么决定？这会影响结论页和内容顺序。A：批准试点（推荐，材料已有明确试点范围）；B：了解进展；C：讨论长期投入。

用户说「你决定」时，对偏好采用推荐值并纳入方案；不能据此编造缺失事实。用户主动一次提供多个答案时全部吸收，不再拆开重复询问。

### 3.3 何时停止

当信息足以形成可评审方案，且不存在必须由用户补充的事实缺口时停止追问。剩余低影响偏好作为可见假设处理。问答目的不是收齐一张表。

已回答内容与关键假设随任务的规划上下文保存，区分用户事实、用户偏好与 Agent 假设。恢复任务时先读取；条件改变只重新讨论受影响的问题。只维护当前有效上下文，不建立问答事件账本或独立审批系统。

## 4. 方案确认页

扩展现有任务内 HTML，内容按以下顺序组织。对话同时提供紧凑摘要和页面链接，不能要求用户必须打开浏览器才能继续。

### 4.1 整体方案

展示标题、受众、目标、核心结论、总页数和叙事思路。关键假设单独标明，不能混入已确认事实。

### 4.2 逐页内容卡片

按正式页序展示每页标题、核心信息和内容关系。完整可见文案及来源可展开查看，展开内容不截断或另行概括。明确标记将用于样页的页面。

卡片是内容规划，不伪装成实际生图结果，不预设每页固定版式。用户可为整体方案或某一页填写修改意见。首版采用意见输入，不做富文本编辑、拖拽排版或 PPTX 在线编辑器。

### 4.3 视觉方向

沿用「风格 → 档位 → 配色」：第一轮展示全部可用风格，第二轮一起展示所选风格的真实档位与配色组合。可在内容与视觉区块之间往返，不增加确认门。

选择数据以当前任务发布的方案快照为准。图床中的 90 张设计图不自动扩展当前运行目录的 34 个配方组合；本设计不修改已接受模板或扩展组合定义。

### 4.4 生成前确认

明确展示已选组合、样页是哪一页、参考图用途、一次新增生成调用及输出位置。选定组合后展示其确切样页出站提示词，包括现有用途说明；可折叠，但必须可以完整查看。

主操作为「确认方案并生成样页」。它同时确认当前内容方案、明确视觉组合并授权一次样页调用。只点击风格、翻页、展开内容或复制普通选款文本，不视为生成授权。

## 5. 页面与 Agent 的交接

首版保持现有本地 HTML 与 Agent 接力方式，不引入页面到 CLI 的后台写入服务。

- 页面选择与填写意见仅更新页面草稿，不修改任务状态或发起生图。
- 「提交修改意见」复制一段可读回复，包含方案版本、页码／标题及修改意见；Agent 收到后沿用 revise-plan 生成新方案并重新展示。
- 「确认方案并生成样页」复制一段明确授权回复，包含方案版本、风格、档位、配色及一次调用预算；页面说明「复制后发送给 Agent 才会执行」。复制成功不能显示为方案已提交。
- 尚未选择完整组合时，不能形成生成授权回复。
- 有待提交修改意见时，先提交修改并回看新方案；不能将「修改后直接生成」混成同一首版操作。
- 复制失败时显示可手动复制的完整文本；不得声称已提交或已保存。尚未发送给 Agent 的页面草稿不保证刷新后保留，页面须明确说明。

Agent 核对回复对应当前发布方案和 pending decision 后再调用既有决定动作。旧页面的回复不能误授权新方案；遇到版本不匹配应展示当前方案，解释需要重新确认。使用现有版本及决定身份，不新增签名或审批链。

用户也可以直接在对话中修改或确认。若此前已展示完整方案、确切已选组合及预算，并明确询问是否生成样页，用户的「确认」可承接该明确上下文；若只在讨论风格，不能扩大其确认含义。

## 6. 数据与实现边界

现有 Brief、Outline、SlideSpec、样页提示词、参考图和方案 revision 是内容权威源。HTML 是这些数据的展示，不维护另一套内容真相。

规划上下文仅补充当前有效回答、假设与叙事摘要；实现时采用任务内轻量持久化，并在提交新方案时固化相关信息。它不创建新的工作流 stage。已有用户修订按当前内容 revision 处理，未变页面保持 ID 与确切规格，延续样页和成功页复用规则。

首版继续使用 select-style-and-generate-sample 和 revise-plan；没有单独的 outline-approved、style-approved 或 questionnaire-completed 动作。对话与 HTML 汇入相同决定路径。

宿主无法打开 HTML 时，按同样顺序提供内容摘要、完整内容文件、原生风格图片和可复制确认文本。图床不可达只影响参考图片显示；页面仍可读、方案仍可修改，选择仍可用。

HTML 对用户文字和引用字段进行正确转义。页面仅向已配置图床请求公开风格图，不将用户文案、修改意见、任务路径或上传 Token 放入远端请求。沿用不发送 referrer 的图片策略。

## 7. 交付顺序

1. 完善 Agent 问答、答案复用和确认语义，先确保纯对话路径完整可用。
2. 扩展现有 HTML，加入方案卡片、修改意见与带当前版本的确认回复；两种入口行为一致。
3. 完成自动化流程验证，以及真实浏览器选款、修改、复制和失败回退验收。

这三个实施步骤不是新增用户审批阶段。当前浏览器策略曾阻断本地产物访问，真实交互验收须在实际允许的宿主能力上完成；没有实测就不能宣称通过，也不能用更换通道绕过明确限制。

## 8. 验收标准

| 场景 | 必须观察到的结果 |
| --- | --- |
| 完整材料 | 不发起无关问卷，直接给完整方案与关键假设 |
| 主题输入 | 一次一个关键问题，推荐理由明确，回答后继续规划 |
| 用户一次回答多个事项 | 全部吸收，后续不重复询问 |
| 中断恢复 | 保留已答事实与当前方案，不重新访问已确认决定 |
| 长方案 | 可按页定位、展开完整文案并提交该页修改意见 |
| 内容修改 | 展示更新后的方案；旧授权文本不能触发新方案生图 |
| 单纯选择风格 | 生成调用为零 |
| 明确确认方案与一次预算 | 只产生一次样页调用，重复继续不增加调用 |
| 有未提交修改 | 先回看修订方案，不能带修改意见直接生图 |
| HTML 不可用或图片加载失败 | 对话／图片失败提示可用，任务可继续 |
| 剪贴板失败 | 提供可手动复制文本，不误报提交成功 |
| 样页与整套 | 三次业务确认节奏保持，已批准样页复用 |

自动化覆盖内容投影、完整文案、版本绑定、预算、失败回退和源码／编译／独立安装后的完整流程。浏览器验收覆盖真实打开、内容展开、风格选择、逐页意见、复制和窄视口；两类证据分别报告。

## 9. 与既有规范的关系

补充精简工作流的方案阶段与 VS-05 展示层。三个业务决策点、全量风格展示、源文案保留、模板边界、样页复用及完整 PPTX 验收继续有效。

不引入强制全流程访谈、逐页审批、多套强制提案、在线编辑器、云端项目服务或旧项目迁移。本稿不代表代码、HTML 或宿主交互已经实现。
