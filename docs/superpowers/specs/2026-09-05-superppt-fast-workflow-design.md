# SuperPPT vNext 精简工作流设计

- 日期：2026-09-05
- 状态：用户已确认（2026-09-05）；本文件描述待实施的 vNext
- 范围：SuperPPT 用户决策流、Agent 编排、生成委托、项目持久化与完整 PPTX 修改交付
- 取代：`2026-08-26-superppt-design.md` 的流程与持久化部分，以及 `2026-08-28-superppt-ai-image-to-ppt-delegation-design.md` 的现有授权实现

## 1. 结论

SuperPPT 继续是一个面向用户的 PPT 编排 Agent，不是本地安全审计系统。

vNext 只保留生成、修改和交付所需的业务状态与工程正确性保护。它删除所有以“防御同一用户机器上的恶意进程篡改项目状态”为目标的签名、权威链、高水位、事件链和一次性准入令牌。不保留严格审计模式、兼容开关或隐藏备用路径。

vNext 的默认快速路径只有三个用户决策点：

1. 方案确认：内容规划、风格选择与样页授权。
2. 样页确认：确认真实样页并授权整套生成。
3. 整套 Review：在真实完整 PPTX 上修改、返回上游或确认交付。

## 2. 产品目标

### 2.1 保留的产品价值

- 从主题、粘贴内容或 Markdown 生成高细节演示文稿。
- 默认生成高保真图片式整套 PPTX。
- 只对用户需要修改的页面做可编辑重构。
- 在付费或对外生图前获得用户明确授权。
- 支持中断恢复，已成功页不重复生成。
- 以 WPS 或 PowerPoint 打开的真实完整 PPTX 作为 Review 和编辑对象。
- 用户手动编辑后，只有在“已保存并关闭”后才采纳该完整文件。

### 2.2 成功指标

- 默认用户等待点不超过 3 个。
- 默认公共 CLI 入口不超过 5 个。
- 整套生成在 SuperPPT 边界上是一个 job 和一个聚合 result，不随页数增加 CLI 往返。
- 每个 job 最多做一次完整依赖预检；依赖指纹未变时不重扫源码树。
- 恢复生成时，已成功页的新增生图请求数为 0。
- 自动化验证不降低现有页数、顺序、尺寸、文件可打开性和选中页可编辑性要求。
- 人工 WPS 验收边界保持不变。

## 3. 非目标

- 不为本地项目状态建立攻击者模型。
- 不防御同账号恶意进程修改项目目录。
- 不提供外部审计、合规存证、事件追溯或不可抵赖证明。
- 不保留 strict、audit 或 paranoid 模式。
- 不读取、迁移或继续执行 vNext 之前创建的旧项目。
- 不默认把全套 PPTX 转为可编辑页面。
- 不把 `ai-image-to-ppt` 或 `image-to-editable-pptx` 复制进 SuperPPT。
- 不实现 Web 预览器、云端项目服务、多人协作或任务队列。

## 4. 三个用户决策点

### 4.1 方案确认

SuperPPT 自动完成导入、必要追问、内容规划和风格推荐，然后在同一次决策中展示：

- 受众、目标、页数和叙事摘要。
- 完整大纲。
- 逐页描述的紧凑摘要；用户可展开查看全量内容。
- 三个与内容匹配的真实风格预览，风格仅能单选。
- 代表页、样页出站内容、参考图用途、一次生图请求和输出位置。

用户的主操作是“选择此风格并生成样页”。该操作同时表示内容方案建立当前基线、风格选择生效，并授权唯一一次样页调用。

用户可在该点直接修改大纲、单页描述、代表页或风格。没有单独的 outline、slide-specs、style-selection 或 style-sample-generation 等待门。

### 4.2 样页确认

SuperPPT 展示真实生成样页，以及整套生成的：

- 总页数和最大生图调用数。
- 出站提示词和参考图用途。
- 输出位置与由宿主 Agent 调用 `ai-image-to-ppt` 的说明。

用户的主操作是“按此风格生成整套”。该操作同时确认样页、冻结当前 Style Lock，并授权一个整套批次。

如果用户要求修改样页，SuperPPT 在用户确认新的一次调用前不继续花费。不存在单独的 style-sample 与 generation-authorization 等待门。

### 4.3 整套 Review

SuperPPT 自动接收整批结果、执行页级 QA、组装完整 PPTX，然后只给用户一个当前完整 PPTX 链接。用户从以下操作中选择：

- 修改某页。
- 返回修改上游内容或风格。
- 确认交付。

修改和交付始终绑定当前 PPTX revision 和文件摘要，用于防止误改或交付一个已被替换的文件。这是业务上的文件身份校验，不是审计签名。

## 5. 自动继续原则

除三个用户决策点、新的付费请求授权、手动编辑的“已保存并关闭”和 Agent 改稿确认外，所有机器可完成的步骤都由 `continue` 自动运行，直到：

- 到达下一个用户决策点。
- 当前任务完成。
- 出现一个必须由用户选择的能力差异或业务失败。

`continue` 必须幂等。重复运行只恢复未完成的机器步骤，不重复生图、不创建第二个候选 PPTX，也不重复要求已完成的用户决策。

宿主工具仍由 Agent 调用。CLI 遇到规划、生图或视觉 QA 时返回机器交接对象；Agent 执行后将结果交回同一个 `continue` 入口。这不是新增人工等待点，也不要求 CLI 内建模型调用器。一个正常完成的生图批次只交接一次；异常中断允许继续同一个 job。

## 6. 公共命令面

vNext 只对 Agent 和用户工作流暴露以下公共命令：

| 命令 | 职责 |
|---|---|
| `start` | 预检并初始化新项目，或恢复同一个 vNext 任务的中断状态 |
| `continue` | 执行所有无需用户决策的步骤，直到下一个决策点或结果 |
| `decide` | 提交当前决策点允许的用户操作，包括绑定的外部调用授权 |
| `edit` | 解析目标页并执行人工修改、Agent 修改、可编辑激活或单页重生路由 |
| `status` | 返回当前项目、决策、job、PPTX revision 和恢复状态 |

现有细分命令可以在模块内部短期作为重构过渡函数，但不再是公共 CLI 或 Skill 指令。新流程完成后删除其入口和仅验证旧命令序列的测试。

## 7. 简化项目状态

`superppt.json` 保持为项目的唯一当前业务状态文件。vNext schema 只包含：

- 项目 ID、标题、源内容位置和 schema 版本。
- 当前阶段与待决策操作。
- 当前内容 revision ID。
- 大纲、逐页描述和 Style Lock 的项目相对路径。
- 当前样页 job、整套 job 和必要的单页重生 job ID。
- 当前完整 PPTX revision ID、相对路径与 SHA-256。
- 当前手动或 Agent 编辑会话。
- 最终交付状态和文件相对路径。

每次状态更新使用“写入同目录临时文件 → fsync 文件 → rename 覆盖 → fsync 目录”。同一项目只使用一个短期进程锁。

`superppt.json` 中的 current deck 字段是唯一权威指针；`output/current.json` 仅为可从它重建的派生视图，不参与双向认证。采纳、交付和回滚在同一次 manifest 更新中改变指针与业务状态。目录 fsync 使用平台支持的实现，不为此恢复原生防篡改封装。

不再维护或验证：

- HMAC key 或签名记录。
- authorization heads、call heads 或 acceptance heads。
- project registry、root authority 或高水位。
- 多份可互相证明的当前状态副本。
- 为防止本地恶意回滚建立的链式事件历史。

## 8. Style Lock

每个内容 revision 最多一个 `style-lock.json`，包含：

- 选中的风格 ID 或自定义风格说明。
- 色彩、材质、光影、构图、文字安全区和禁止项。
- 代表页 ID。
- 参考图路径、用途和文件摘要。
- 样页确认前为 `provisional`，确认后为 `approved`。
- 批准样页的路径和文件摘要。

风格选择、配方和锁定不再是三份相互绑定的文件。上游修改时，SuperPPT 计算影响并直接在新的内容 revision 中复用或重建 Style Lock；不执行旧证据退役交易。

## 9. 生成委托契约

SuperPPT 与 `ai-image-to-ppt` 之间只有两个契约。

### 9.1 `ImageGenerationJob`

一个 job 至少包含：

- job ID、kind 和当前内容 revision ID。
- 当前 Style Lock 快照。
- 按顺序排列的页面 ID、prompt、目标路径和初始处置（`pending` 或 `cached`）。
- 总生图调用上限。
- 已验证成功、需作为 cached 恢复的页面。
- 当次用户授权所覆盖的出站内容摘要。

job 发布后不就地修改。上游变更、新的样页请求或新的页面重生都创建新 job。

### 9.2 `ImageGenerationResult`

`ai-image-to-ppt` 把整份 job 作为一个串行批次执行，然后返回一个聚合 result，至少包含：

- job ID、outcome 和实际生图请求总数。
- 批次路由摘要。
- 每页的 success、cached、failed 或 paused 状态。
- 每页实际 provider/channel、输出路径、文件摘要和必要 QA 结果。
- 参考图是否被使用或不受当前路由支持。

正常完成时，SuperPPT 对整份 result 做一次聚合接收。相同结果重复提交返回已有状态；中断后的 partial 结果可通过同一 job 的 checkpoint 继续为完整结果，已成功页不得改变。接收器验证 job ID、页面集、调用总数、输出位置、文件可解码性、16:9 尺寸和摘要，然后一次性更新项目。不为每页发布准入 token，不为每页召回 SuperPPT CLI，也不在 SuperPPT 里复制 provider 路由状态机。

### 9.3 批次检查点

`ai-image-to-ppt` 在 job 目录内逐页落盘结果，并维护一份可原子更新的本地 checkpoint。SuperPPT 恢复时把已成功且文件仍可读的页面作为 cached 交回依赖。checkpoint 只服务于崩溃恢复和避免重复花费，不构成签名账本。

调用预算必须在实际请求前执行，不能只在超额消费后拒收。宿主 Agent 执行批次时保存累计请求数和当前在途页；失败请求仍计数，恢复不重置余额。请求已发出但回执因中断丢失时，先寻找已有产物；无法确认结果时报告该页待处理，不自动重复付费。该 checkpoint 是普通本地状态，不使用 token 或签名。

## 10. 授权边界

用户授权与有意义的业务操作合并：

- “选择此风格并生成样页”授权一次样页调用。
- “按此风格生成整套”授权一个具有明确总上限的批次。
- “重新生成该页”授权一个明确的新页面 job。

用户决策记录只需保存决策 ID、时间、内容 revision、job ID 和授权上限。不签名，不写外部权威目录，不建立链式记录。

任一上游内容变更都使未执行的授权失效。这通过直接比较当前 revision ID 与 job 中的 revision ID 实现，不通过外部信任链实现。

## 11. 依赖预检

`start` 解析已安装依赖的规范物理根目录。输入可以是可解析的安装链接，不要求 Agent 手动猜测物理 package root。

完整预检验证：

- 依赖身份和兼容版本。
- 必需入口和脚本是否存在。
- 当前依赖指纹。
- 本地文件、宿主生图和完整 PPTX 交接能力。

依赖绑定缓存在项目内。每个新 job 先做便宜指纹检查；只有指纹改变、缓存缺失或兼容版本不再满足时，才重新执行完整预检。

## 12. 完整 PPTX 修改与交付

### 12.1 保留的修改模型

- `current.json` 指向唯一当前完整 PPTX revision。
- 每个 revision 保留完整 PPTX、页面拓扑、可编辑页 ID 和必要的复核对象。
- 修改在当前 revision 副本上完成，采纳时原子切换 current pointer。
- 回滚只切换 current pointer，不改写历史 PPTX。

### 12.2 手动修改

SuperPPT 复制当前完整 PPTX 作为一个候选 revision，给用户一个链接，然后等待精确的“已保存并关闭”信号。收到后：

1. 稳定读取已关闭文件。
2. 校验它是可打开的完整 PPTX。
3. 重新校准页面移动、新增、删除和稳定页 ID。
4. 记录实际文件摘要和拓扑。
5. 不重写 PPTX，直接把 current pointer 切换到该文件。

### 12.3 Agent 修改

Agent 在候选 revision 上完成修改，并展示唯一完整 PPTX 与文件摘要。用户确认后才切换 current pointer。候选被拒绝时不改变 current。

### 12.4 正式交付

用户确认当前 revision 交付后，SuperPPT 在 `交付/<项目标题>.pptx` 发布同一份字节。如果同名用户文件已存在且内容不同，使用稳定的短摘要后缀，不覆盖原文件。

最终状态只记录交付 revision、相对路径、SHA-256 和时间。不创建交付签名、acceptance chain、client authority 或外部登记。

## 13. 上游修改

用户可随时修改大纲、一页或多页描述、代表页或风格。SuperPPT 计算受影响的稳定页 ID 和需重建的下游产物。

只有当修改会产生新的付费调用、丢弃尚未交付的人工编辑，或覆盖用户已确认的当前方案时，才需要一次确认。影响结果直接作为该决策的说明，不另建 revision-impact 等待阶段、不发布待二次批准的影响计划文件。

新 revision 只保留未受影响的已验证页和文件，不通过证据链或历史权威记录证明它们可以复用。

## 14. 错误与恢复

### 14.1 可自动恢复

- 规划、编译 prompt、本地格式转换或组装中断：`continue` 从最近已完成步骤恢复。
- 生成批次中断：已成功页作为 cached，只继续未完成页。
- 状态写入中断：原文件或完整新文件二选一，不接收部分 JSON。
- PPTX 候选采纳中断：根据候选 revision 和 current pointer 幂等完成或返回 Review。

### 14.2 必须停止

- 依赖缺失或版本不兼容。
- 当前 provider/channel 不支持必需的 `art-direction` 参考图。
- 整批实际请求数超过用户授权上限。
- 结果引用不属于当前 job 的页面或产物。
- PPTX 不可打开、页面拓扑不可校准，或编辑目标已不是当前 revision。

这些停止是业务或正确性失败，不使用“信任链损坏”、“权威回滚”等安全审计错误类型。

## 15. 旧项目与兼容策略

PPT 制作是一次性任务。vNext 只创建新 schema 项目，只恢复同一个 vNext 项目在当次制作中的中断状态。

vNext 不实现旧项目迁移器，不读取旧 schema，不识别旧审计链，不回写旧工作区，也不保留旧命令兼容层。如果 `start` 指向旧 schema 或非空的旧 SuperPPT 工作区，它必须在任何写入前停止，明确要求选择新的空项目目录。

现有旧项目文件不由 vNext 修改或删除。这只是对用户文件的非破坏性保护，不是兼容支持。

## 16. 删除范围

实现 vNext 时必须删除而不是继续包装以下能力：

- `src/generation/trusted-authorization.ts` 及其安全审计调用链。
- 逐页 `admit-image-call`、一次性 admission token、逐页 call settlement 和 trusted call ledger。
- authorization/call/acceptance heads、events、registries、root authorities 和 high-water marks。
- 为证明旧风格证据可删除而建立的退役交易和多文件证明链。
- 已从公共 CLI 移除的 candidate review 旧实现、离线旧验收入口及仅为它们存在的测试。
- 仅用于防御本地恶意状态替换、回滚或重放的 schema、错误类型、fixture 和文档。

不允许把上述代码改名为“可选严格模式”后保留。

## 17. 保留范围

以下能力属于工程正确性或产品核心，必须保留：

- 项目所有权标记和项目相对路径约束。
- 原子写、同目录 rename、必要的 fsync 和单项目短期锁。
- 普通文件、目录和非符号链接的项目产物检查。
- 内容 revision、job ID、PPTX revision 和 current pointer。
- 用于文件身份、缓存和幂等的 SHA-256；不将它提升为外部信任证明。
- 总调用预算、串行路由、成功页 checkpoint 和断点恢复。
- 页级 QA、完整 PPTX 组装和真实文件 Review。
- 选中页可编辑重构、WPS/PowerPoint 手动编辑、页面拓扑校准和指针回滚。
- 语义化最终文件名和不覆盖用户文件。

## 18. 测试策略

### 18.1 保留并改造

- 从导入到方案确认的集成测试。
- 三个决策点的状态机与非法操作测试。
- 一个样页 job 和一个整套 batch job 的端到端测试。
- 实际请求总数不超过授权上限的测试。
- 生成中断后恢复且不重生成已成功页的测试。
- `continue` 在每个本地步骤中断后的幂等恢复测试。
- 完整 PPTX 候选、手动采纳、Agent 确认、页面拓扑校准、最终交付和指针回滚测试。
- 真实 WPS 的编辑 → 撤销 → 明确保存/不保存 → 重开验收。

### 18.2 删除

- HMAC 密钥、签名、链验证、头文件和外部 registry 测试。
- 本地攻击者替换、重放、删除或回滚审计证据的测试。
- 每页 admission token 生成、消费、结算与链式 ledger 测试。
- 仅证明旧 36 命令编排顺序的测试。
- 旧 candidate review 和旧 acceptance 入口测试。

## 19. 实现与交付顺序

vNext 作为一个架构重构交付，实现顺序是：

1. 定义精简状态、三个决策和五个公共命令的新 schema。
2. 实现新的整批 job/result 和中断 checkpoint。
3. 把生成、组装、Review 与修改收敛到 `continue` / `decide` / `edit`。
4. 用精简状态替换 trusted authorization 和旧风格证据流。
5. 删除审计实现、旧 Review 契约、旧公共命令、旧测试和对应文档。
6. 通过端到端、可携带、完整发布检查和真实 WPS 验收后发布。

分步编码可在开发分支中短期保留内部过渡函数，但最终发布不包含两套公共流程、旧项目迁移器、strict 开关或审计代码。

## 20. 验收条件

vNext 只在同时满足以下条件时算完成：

1. 新项目从导入到交付最多经过三个默认用户决策点。
2. 整套 N 页生成只有一次 SuperPPT → `ai-image-to-ppt` job 交接和一次聚合 result 接收。
3. 公共 CLI 只包含 `start`、`continue`、`decide`、`edit` 和 `status`。
4. 生产代码不再包含 trusted authorization、admission token、authority/head/event/registry/high-water 实现或 strict 模式。
5. 本地中断恢复、调用预算、已成功页缓存和原子状态更新仍然有自动化证据。
6. 生产代码不包含旧项目迁移器或旧 schema/CLI 兼容层；旧工作区在任何写入前被明确拒绝。
7. 完整 PPTX 修改、“已保存并关闭”采纳、Agent 确认、回滚和语义化交付不退化。
8. 真实 WPS 验收完成前，只能报告自动化验证完成，不能宣布最终交付验收完成。
