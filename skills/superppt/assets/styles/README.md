# 十一风格运行资产

`catalog.json` 是唯一的运行时风格定义，顺序为商务风格、立体、玻璃、水墨、经典手绘、教材图解、创意拼贴、电影科技、奢华摄影、建筑蓝图、叙事幻想。每种风格都有 1／2／3 档 × 偏冷／基准中线／偏暖，共 99 个可选组合、99 张精确预览和 11 张代表展示图。

配色是各自风格基准的相对变化，中线不等于黑白灰。生产模板包含 `{{PALETTE}}`、`{{CONTENT_RELATIONSHIPS}}`、`{{SLIDE_COPY}}` 各一次，选款后完整配方进入样页和整套生成。自定义风格仍允许较少组合和明确标识的缺图状态。

## 图片来源与加载

第一轮代表图使用 `showcases/<styleId>.jpg`，第二轮精确预览使用 `previews/<styleId>-<level>-<palette>.jpg`。这些是逻辑键，实际 URL、SHA-256、字节数和尺寸存放在 `remote-assets.json`。图片为图床上的 PNG；安装包不包含图片二进制。规划读取本地索引，浏览器打开页面时加载公开 HTTPS 图片，不触发生图调用。

非商务的 90 张参考图来自 `ten-styles-ninety-variants-r1`，已在 2026-09-08 整体验收并上传。原图、提示词和修改记录保存在维护工作区的历史批次目录中，运行时不依赖该目录。2026-09-27 修复了上传索引与运行目录脱节的问题：补齐立体 1 档中线、玻璃 1／2 档偏冷，并恢复其余七种风格的全部九种组合。预览溯源已切换到这批最终验收图片；远端图片 SHA-256 必须与溯源一致。

商务保留 `business-layout-v2` 的九张已接受参考图，代表图复用 3 档中线。远端注册表还保留历史风格键；当前页面只使用目录引用的 110 个逻辑键、99 个唯一图片 URL，不会因此展示历史候选。

## 配方来源

立体、玻璃、水墨的三档模板与色板保持原有生产定义。原七种扩展风格的 3 档中线模板保持 `ten-style-showcase-v1` 的已接受抽取结果，并保留原 `acceptedSource`、`recipes` 和 `recipeTransformations` 溯源。

新增的一、二档从已验收九宫格批次对应的基准提示词抽取，替换配色、内容关系、可见文案为三个槽，去掉固定广告文案与样例用途说明；教材图解的英文硬编码色号改为遵循所选色板，避免覆盖冷暖选择。新增冷暖色板沿用该批次 `candidate-palettes.json`。`variantRecipes` 记录这些配方的来源与模板哈希，`variantSource` 记录验收批次清单哈希，`previews` 记录原图和提示词哈希；有修图记录的预览同时记录修图提示词哈希。

商务以文字层级和留白为主，图形用于小型语义图标与有输入数据支持的图表，不编造数字，正文不使用流光。商务模板与色板由 `businessRecipes` 单独校验。

已接受图片是风格参考，不代表任意新文案都能稳定生成相同布局或逐字无误；新生成的幻灯片仍须验收。

## 验证

```sh
node scripts/build-style-catalog.mjs
npm test
```

构建校验每种风格的三档、三种配色、九张唯一精确预览、模板槽、路径、来源哈希及远端资源元数据。正常验证不联网、不生图、不下载图片。

商务原始来源可独立检查，且不会改写目录：

```sh
node scripts/build-style-catalog.mjs --business-source-dir /path/to/business-layout-v2
```

历史 `--normalize-previews --accepted-source-dir /path/to/ten-style-showcase-v1` 只重建旧来源代表图；不会覆盖当前九宫格批次。其产物不是运行必需资产，打包仍排除预览和展示图片目录。
