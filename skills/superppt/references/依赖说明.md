# CLI 与机器工作

从插件根目录运行 npm run cli -- --help。公共命令只有：

```text
start --project <新空目录> --input <source.json> --dependencies <roots.json>
continue --project <任务目录> [--result <work-result.json>]
decide --project <任务目录> --input <decision.json>
edit --project <任务目录> --input <edit.json>
status --project <任务目录>
```

source.json：{title,text} 或 {title,markdownPath}，恰选其一。roots.json：{aiSkillRoot,editableSkillRoot}，填实际安装绝对路径。
start 保存原文、解析入口并返回 plan work。重复 start 仅可恢复同版本且源字节相同的任务。
依赖只有每批次一次轻量入口检查，无全源码扫描；安装改变时重新用相同 source/roots 执行 start 刷新。
每个宿主会话重新确认实际可调用图像工具；安装文件不证明在线能力。

## 结果回传

所有 work 统一写 JSON：
{workId: work.id, contentRevision: superppt.json.contentRevision, payload: ...}
保存到 work.resultPath，再运行 continue --result <绝对路径>。
读取 work.inputPath；所有文件相对路径相对于任务目录。
相同成功结果可重试，不重新执行生成。过期 work 或内容 revision 不接收。

plan payload 的完整结构见 src/workflow/contracts.ts 的 PlanBundleSchema；可选 context 为 {schemaVersion:1,narrativeSummary,answers:[{key,value,kind:"fact"|"preference"}],assumptions}。旧 plan 可省略 context；新发布 plan 会将有效上下文固化到方案快照。
样例创建方式见 tests/helpers/fast-task.ts（仅开发测试，不随发布包）。
plan work 的 request.planningContextPath 指向 planning/<contentRevision>/context.json。开始或恢复时先读源材料、该文件及 previous（若存在）；每次用户回答后立即更新该文件，同一次回答中的多个事实／偏好一次吸收，不重复追问。损坏或非法 context 必须报错，不能当空上下文继续。完整且目标明确的材料直接规划；只有高影响缺口才一次问一个问题，不能把受众和目标合并成所谓“关键一点”。只有主题时先单独问受众，给 2–3 个选项并说明推荐理由；下一轮仅在仍未知时再问目标。缺少事实来源时只问该项事实。低影响默认值列入 assumptions。不得编造数字、结论、承诺或 PlanBundleSchema 外字段；时长写 brief.constraints/context，不写 Brief.duration。不强制多套方案，不擅自重构已批准原稿。
Agent 使用 brief、outline、slides、styles、representativeSlideId 和当前有效 context；保留来源，不用省略号代替逐页内容。
slides 每页包含 schemaVersion:1、slideId、title、role、coreMessage、requiredText、relationships、forbidden、sourceRefs。requiredText 包含标题及全部可见文案，按阅读顺序逐项完整保留；无 visualSubject／composition 字段。relationships 写语义关系，不替模型指定画面几何。
styles 默认从 assets/styles/catalog.json 原样取全部十个条目：id、name、tiers[{level,promptTemplate}]、palettes[{id,name,prompt}]、previews[{level,paletteId,path}] 和可选 showcase。用户明确给出的自定义 plan.styles 保持权威，不用默认目录重写；自定义风格沿用同结构，不声称它经过预览验证。
plan-review 的 details.selectionOrder 是 styleId → level → paletteId。details.selection 包含第一轮风格卡和按档位分组的第二轮组合；新发布任务的 details.selectionPath 是任务相对的 HTML。details.planPath 是已发布方案；新任务的 details.reviewModelPath 是页面与对话共用的快照，此时 details.contentRevision 必须等于 review model 的 revision，当前 decision.id 必须等于 review model 的 decisionId。恢复只读取并校验已发布文件，不用当前目录资产重建；历史 plan-review 没有 HTML 或 review model 时省略对应路径，保留 planPath、samplePromptsPath、文字列表、details.selection、previewBase 和 styles 作为只读回退，不要求缺失的 review model。回复正文同时给出可用 HTML 的本地绝对链接和全部风格名，供纯文本宿主回退。纯对话优先按 planPath/reviewModelPath 展示标题、受众、目标、页数、叙事摘要、事实／偏好／假设、逐页 coreMessage、完整 requiredText、relationships、sourceRefs 和样页标记；没有 review model 时用 planPath 和当前 details 展示同样的方案信息。选择组合后优先从 reviewModel.variants[styleId/level/paletteId].prompt 展示确切实际出站 prompt；没有 review model 时从 samplePromptsPath 取对应内容 prompt，并附 details.submissionNote，最终同时披露 references、callBudget:1、output 和生成样页动作。只展示该风格真实可用的档位与配色，基准中线是其确认色系，不是黑白灰。details.previewBase 为原生内联回退使用的预览根目录。previews 是精确组合索引，缺项明确标为缺少精确预览，但配方仍可选，不能生成或冒充。
选择 HTML 从图床加载公开 HTTPS 图片；生成选择页和处理选择本身不需要网络。图片加载失败会显示提示，仍可选择。原生图片回退先读取 previewBase 下的 remote-assets.json，以 showcase.path 或 previews[].path 查询 assets[逻辑路径].url；没有远端条目时再读取自定义本地图片。第一轮看完所有风格后，第二轮在同一页面查看所选风格的全部组合并复制自然语言元组，例如“选择创意拼贴，3 档，基准中线”。点击页面不会写决定、创建作业或消耗预算；风格元组本身也不是生成授权。Agent 在既有 plan-review 边界披露确切样页 prompt、参考图用途、预算 1 和输出位置，并取得明确生成授权后，才提交 select-style-and-generate-sample。HTML 不可用时按相同顺序用宿主原生图片与文字元组回退；这不代表远程移动端已验收。
details.samplePromptsPath 指向按 styleId/level/paletteId 索引的候选样页内容 prompt（如 glass/2/cool）；只有字符串预编译，不会调用生图。sample-review 的 details.promptsPath 指向整套内容 prompt。用文件链接披露选中组合的完整文本，并展示 details.submissionNote；实际出站文本由原内容、两个换行、此说明组成。不要把所有组合或整套长 prompt 展开到对话。
decide 输入：{decisionId,action,...}。正常动作：

- select-style-and-generate-sample：styleId、level（1／2／3）、paletteId（该风格实际可选 ID）、callBudget:1；三项明确选择，不静默使用默认值。
- approve-sample-and-generate-deck：callBudget（使用 sample-review 的 details.callBudget，覆盖未缓存页面；全部复用时为 0）。details.pageCount 是整套页数，generationPageCount 是新生成页数，reusedSlideIds 标识复用页，不能将整套页数误报为新增请求数。
- confirm-delivery：确认已展示的当前完整 PPTX。
- revise-plan：instruction。
- regenerate-page：pageNumber、instruction、callBudget；限 deck-review。
- retry-generation：callBudget；限 generation-recovery，成功页自动复用。
- saved-and-closed、confirm-agent-edit（confirmedSha256）、reject-edit、rollback-deck。

edit 输入：{pageNumber,mode:"manual"|"agent",route:"direct-edit"|"activate-editable",instruction}。

选款确认示例：{"decisionId":"当前决定的 UUID","action":"select-style-and-generate-sample","styleId":"glass","level":2,"paletteId":"cool","callBudget":1}。
若用户发来页面生成的带版本回复，先将“方案版本”与 details.contentRevision、“决定编号”与当前 decision.id 逐字核对。任一不匹配时不得替换成当前 UUID 后继续，须返回当前方案并让用户重新确认。回复已包含当前版本、当前决定、确切组合和预算 1 的授权，且完整 prompt、参考图用途、generation 输出位置此前均已披露时，直接构造上述 decide 输入，不重复询问。纯对话中的简短“确认”可承接紧邻且无歧义的当前披露；不能承接仅选风格或旧版本的上下文。
styleLock.recipe 保存 {id,name,level,paletteId,promptTemplate}；其中已挂载所选配色，只保留 CONTENT_RELATIONSHIPS、SLIDE_COPY 两个内容槽位。样张与整套复用这个快照，不重新读取目录选另一套提示词。玻璃 cool 的三个档位共用黑蓝配色，1 档仍为薄毛玻璃。

## 批次执行

读取已解析 ai-image-to-ppt/SKILL.md 及其 host-image-routing.md，整个 work 建立一个 SerialStickyRouter。
该路由器是依赖 Python 模块；由宿主 Agent 提供实际工具调用回调，不能发明 batch CLI，也不能用 API 脚本模拟宿主工具。
同一次机器工作中串行处理 job.pages；保持一个路由器实例直到结束。当前候选、sticky、fallback 规则均由依赖负责。
中断恢复保持原 job/预算，读取已完成页和历史实际路由；已成功页不再请求，不能重置预算。
无修改批准的样页已按 stable slideId 放入正式 job 的 cached 和 checkpoint.completed，位于原大纲位置。跳过它的 beginRequest 和生图，聚合结果使用原 artifact；无需复制或覆盖原样页及 raw。只请求未完成页，全部缓存时零调用回传聚合结果。批准样页仍与全部页面一起进入 review-images 检查，不另加确认关卡。

批次内直接导入 SuperPPT 的 src/generation/task-batch.ts（Node 使用 --import tsx）：

```typescript
import { readBatchJob, readBatchCheckpoint, beginRequest, finishRequest } from './src/generation/task-batch.js';
// root 和 jobId 来自当前 work，不猜测目录。
// 每个实际外部请求（包含 fallback）前：
const prompt = await beginRequest(root, jobId, slideId);
// 将返回的 prompt 原样传给当前路由的宿主工具或 API helper，再执行实际请求。
// 请求后 await finishRequest(root, jobId, pageResult)。
// 能力不可用的纯探测不调用 beginRequest；不在此处运行公共 CLI。
```

pageResult：
{slideId,status:"success"|"failed"|"paused",artifact:{path,sha256}|null,raw:{path,sha256}|null,provider,channel:"host"|"api",referencesUsed:[]}
成功 master 必须写 job.pages[].target 且为严格 16:9；channel=host 时 raw 必填并保留原始字节。
使用 job.styleLock.recipe、approvedSample、references；job.pages[].prompt 保留原内容，job.generationIntent 从已批准 brief 的 purpose、audience 保存真实用途快照。
beginRequest 只在提交边界附加用途说明并返回完整 prompt，不回写内容 prompt；样页、整套、单页重绘和获授权的重试都用这个返回值。说明非画面文字，模型自行选择适合实际用途的呈现方式，全部可见文案、风格、档位、配色保持不变。不要自行另加用途、统一标成教育、删改正文或叠加敏感词预筛查。安全拒绝按原失败流程记录，不将用途说明当作过滤豁免。
外部参考图必须展示用途；不支持 art-direction 时停止，不偷偷降级。
调用依赖的宿主 importer 或 API helper 完成本地落盘；禁止追加依赖默认风格。
API 调用使用依赖已有的 gen_slide.py --engine <路由选中provider> --retries 0 --json；关闭内部重试，每次实际请求均经过 beginRequest。重试与 fallback 在批次内消耗同一余额。

每页结束记录 checkpoint，但不逐页回传 SuperPPT。整批结束统一 payload：
{jobId,outcome:"success"|"partial"|"failed"|"attention",requestCount,pages:[...],routeSummary:[...]}
pages 必须包含全部页，缓存项 status="cached"，artifact 取 checkpoint.completed，无调用时 provider/channel 可为 null。
未执行项用 paused。requestCount 是 checkpoint 累计值，包含失败。
正常路径一次聚合回传；partial 恢复仍用原 work 和剩余预算。
预算耗尽可经用户授权 retry-generation 新预算，仅剩余页进入新批次。
inFlightSlideId 非空时先确认已有产物并 finishRequest；无法确认则报告不明，绝不自动补发。

## 视觉 QA 与编辑

review-images payload：
{pages:[{slideId,sha256,requiredText:[{text,present}],styleConsistent,hierarchyClear,forbiddenContentAbsent,notes}]}
实际查看每张图，逐字核对当前规格。错误进入 quality-review，由 revise-plan 修正；不导出错误 deck。

convert-page：读取 conversion-request，调用独立 image-to-editable-pptx 的当前 Skill，返回 {outDir}。
CLI 会把单页 donor 拼入完整候选；不重绘其他页。转换可能产生额外费用，必须先向用户说明并获得该页转换授权。
edit-deck：读取 editing 请求，修改目标页并回传 {edited:true}，或提交前述结构化 operations。
仅机器步骤完成后展示完整候选并等确认；不要把可编辑元素识别结果当作已完成修改。
