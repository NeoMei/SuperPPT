# 依赖与命令说明

## 依赖边界

- `ai-image-to-ppt`：每次解析都显式传 `--ai-skill <resolved-root>`，并绑定 Skill 入口和所需脚本的完整性摘要。SuperPPT CLI 只发布计划、不可变 job、一次性调用准入和结果接收记录；Agent 只在获授权 job 已就绪时 read the resolved `ai-image-to-ppt/SKILL.md` 并调用该 Skill。CLI 不执行 provider，SuperPPT 不选择 provider/channel，也不自行渲染图片。
- `image-to-editable-pptx`：要求稳定版 `>=0.2.0 <0.3.0`。预检严格绑定显式选择的本地根目录、`package.json`、`.codex-plugin/plugin.json`、Skill 入口、CLI 入口和 `src/` 树摘要；package/plugin 的名称、版本、Node engine、CLI script 与 skills 路径必须一致。SuperPPT 不解释或证明插件的任意 TypeScript 语义；这些 SHA-256 只证明本次工作流内身份未漂移，不代表发布者真实性。转换输入必须是完整解码的 1280×720 PNG，并且只转换 action 绑定的选中页。
- 插件的每次输出都按不可信产物处理：调用前最后一次复核完整 workflow attestation，调用后再验证 ownership marker、manifest v2、ledger v2、`slide-editable.pptx`、四类对象名、OOXML 关系与 media hash；全部通过后才可进入候选激活。
- 不复制或自动安装依赖，不按模型名切换编排，不从环境变量或相邻目录发现 Skill。CLI 无 `--help` 契约，不得编造路由或 flags。

## 授权与不可变委派

每次样页或整套外部/付费授权前，向用户展示：精确出站文本/提示词、每张参考图及用途（`style-reference`、`subject-reference`、`art-direction`）、页数与最大调用次数、输出位置，以及“宿主 Agent 将调用 `ai-image-to-ppt`”。实际 provider/channel 由依赖的 host routing 决定，结果返回后再展示；provider/channel 变化时不要求用户重述 Style Lock。

持久化 job schema 用 `content-reference` 承载用户可见的 `style-reference`/`subject-reference`，用 `art-direction` 承载同名用途；映射不得改变参考图字节、路径、顺序或哈希。若 structured result 表明 `art-direction` unsupported，停止当前页并解释，不得降级成普通内容参考。

样页与整套 job 的 sealed inputs 不同：

- `style-sample` job：provisional Style Lock，精确 recipe/hash/reference snapshots，`approvedSample: null`，代表页 spec/final prompt，以及 one-call authorization。
- `deck` / `page-regeneration` job：approved Style Lock，authenticated non-null approved sample，精确 recipe/hash/reference snapshots，page-specific spec/final prompt，以及 generation authorization。

两类 job 都把声明的字节、路径、顺序和哈希原样交给依赖，不能让样页 job 伪装成已经拥有 approved sample。逐页串行执行：先 `admit-image-call` 取得精确一次性 token，再调用依赖，再用私有 `record-image-result`/`route-report` 回填；不并行，不重新生成已经成功的页面。明文 admission token 只能出现在当次响应与随后 `0600` 私有 result 中，不能写入项目 ledger、日志或其他输出。

## 当前 Task 10 CLI 路由

只使用下列已实现路由和精确 flags：

| 用途 | 路由 |
|---|---|
| 依赖预检/项目 | `preflight --ai-skill --editable-skill`; `init --project --title`; `status --project`; `ingest --project` + 且仅一个 `--description/--text/--markdown` |
| 规划/门禁 | `validate-outline --project`; `validate-plan --project`; `publish-sample-generation-plan --project --ai-skill --editable-skill`; `approve --project --gate style-sample-generation`; `prepare-style-sample-job --project --ai-skill --editable-skill`; `finalize-style-sample --project --job-id`; `publish-style-sample --project`; `approve --project --gate <outline\|slide-specs\|style-sample\|generation-authorization>` |
| 影响/恢复 | `impact --project --change`; `approve-impact --project --sha256`; `apply-impact --project`; `rollback --project --revision`; `recover-rollback --project` |
| 生成/结果 | `publish-generation-plan --project --ai-skill --editable-skill --call-budget`; `approve --project --gate generation-authorization`; `prepare-deck-job --project --ai-skill --editable-skill`; `admit-image-call --project --job --slide --attempt --request-ordinal --ai-skill --editable-skill`; `record-image-result --project --job --result --route-report`; `prepare-page-regeneration-job --project --request --ai-skill --editable-skill`; `generation-status --project` |
| 私有页面准备 | `convert-page --project --slide --ai-skill --editable-skill`; `promote-editable --project --slide --revision --element --kind`; `plan-edit --input`; `apply-edit --project --slide --revision --input`；这些结果不作为用户交接物 |
| 完整本地演示文稿 | `current-deck-link --project`; `prepare-manual-deck --project --slide-id [--conversion-root]`; `adopt-saved-deck --project --session-id --user-signal saved-and-closed`; `prepare-agent-deck --project --route [--conversion-root] [--generation-job-id]`; `confirm-agent-deck --project --session-id --sha256`; `reject-deck-candidate --project --session-id`; `rollback-deck --project --revision-id` |
| 交付验收 | `acceptance --project`; `acceptance-smoke-copy --project`; `acceptance-record --project --input`（只接收真实的撤销/丢弃/重开证据） |

`record-image-result` 只接收与 immutable job 和已准入 tuple 完全一致的私有 result，并验证串行黏性 route-report。QA 必须覆盖 required text、风格一致性、层级、内容细节和禁用项。页面重生 request、result、route-report 和 edit-plan 均用 `0600` 私有文件。

宿主能力对象必须由 Agent 注入，且明确包含本地文件系统和本地文件链接能力；不得从 TTY、操作系统、WPS 安装或路径存在推断。每次用户交接只显示一个由上述完整演示文稿路由返回的 angle-bracket Markdown 链接。手动路径展示后停止，等用户精确回复 `已保存并关闭` 才把内部 `saved-and-closed` 传给 adoption；Agent 路径展示后停止，等用户精确回复 `确认`，并把确认绑定到已展示的 SHA-256。adopt、confirm、rollback 的状态回执不直接展示路径，后续统一调用 `current-deck-link`。

`deck-review` 不得用通用 `approve`。`return-upstream` 只选择返回前序，不直接改 stage；按 `修改大纲 / 修改第 N 页描述 / 换风格` 生成 change 文件后，依次 `impact`，展示并等待，精确确认后才 `approve-impact` → `apply-impact`。最终 stage 只能取已认证 plan 的 `restartStage`。

## WPS/PowerPoint 受控 smoke

先运行 `npm run cli -- acceptance-smoke-copy --project <root>`，只打开返回 `copy.path` 的受控 `deck-smoke.pptx`。选定并记录一个具体文字/对象，临时修改并记录观察到的变化，撤销并记录结果，选择 discard/no-save（不保存）并记录丢弃结果，关闭、重开，确认并记录原内容恢复结果。绝不打开或保存 canonical `output/revisions/<n>/deck.pptx`，也不要求保存 smoke 修改。

人工真实完成后，把 `application`、descriptor path、非空选定对象、`temporaryEditObserved:true`、`undoObserved:true`、`saveDecision:"discarded"`、`reopenObserved:true`、重读受控副本得到的 `reopenedCopySha256`、观察结果和确认时间写入私有 `0600` JSON，再运行 `npm run cli -- acceptance-record --project <root> --input <file>`。route 会重新读取受控副本与 canonical，认证 descriptor、初始哈希、项目/修订和 immutable observation；只有成功记录才是正式交付边界。不得虚构观察、保存或 hash。
