# 依赖与命令说明

## 依赖边界

- `ai-image-to-ppt`：每次解析都显式传 `--ai-skill <resolved-root>`，并绑定 Skill 入口和所需脚本的完整性摘要。SuperPPT CLI 只发布计划、不可变 job、一次性调用准入和结果接收记录；Agent 只在获授权 job 已就绪时 read the resolved `ai-image-to-ppt/SKILL.md` 并调用该 Skill。CLI 不执行 provider，SuperPPT 不选择 provider/channel，也不自行渲染图片。
- `image-to-editable-pptx`：要求 `>=0.1.0 <0.2.0`，每次转换显式传 `--editable-skill <resolved-root>`，输入必须是完整解码的 1280×720 PNG；只转换 action 绑定的选中页。
- 不复制或自动安装依赖，不按模型名切换编排，不从环境变量或相邻目录发现 Skill。CLI 无 `--help` 契约，不得编造路由或 flags。

## 授权与不可变委派

每次样页或整套外部/付费授权前，向用户展示：精确出站文本/提示词、每张参考图及用途（`style-reference`、`subject-reference`、`art-direction`）、页数与最大调用次数、输出位置，以及“宿主 Agent 将调用 `ai-image-to-ppt`”。实际 provider/channel 由依赖的 host routing 决定，结果返回后再展示；provider/channel 变化时不要求用户重述 Style Lock。

持久化 job schema 用 `content-reference` 承载用户可见的 `style-reference`/`subject-reference`，用 `art-direction` 承载同名用途；映射不得改变参考图字节、路径、顺序或哈希。若 structured result 表明 `art-direction` unsupported，停止当前页并解释，不得降级成普通内容参考。

把一份 Style Lock 的 exact recipe/hash、approved sample、page-specific spec/final prompt 和 reference snapshots 原样交给依赖。逐页串行执行：先 `admit-image-call` 取得精确一次性 token，再调用依赖，再用私有 `record-image-result`/`route-report` 回填；不并行，不重新生成已经成功的页面。明文 admission token 只能出现在当次响应与随后 `0600` 私有 result 中，不能写入项目 ledger、日志或其他输出。

## 当前 Task 10 CLI 路由

只使用下列已实现路由和精确 flags：

| 用途 | 路由 |
|---|---|
| 依赖预检/项目 | `preflight --ai-skill --editable-skill`; `init --project --title`; `status --project`; `ingest --project` + 且仅一个 `--description/--text/--markdown` |
| 规划/门禁 | `validate-outline --project`; `validate-plan --project`; `publish-sample-generation-plan --project --ai-skill`; `approve --project --gate style-sample-generation`; `prepare-style-sample-job --project --ai-skill`; `finalize-style-sample --project --job-id`; `publish-style-sample --project`; `approve --project --gate <outline\|slide-specs\|style-sample\|generation-authorization>` |
| 影响/恢复 | `impact --project --change`; `approve-impact --project --sha256`; `apply-impact --project`; `rollback --project --revision`; `recover-rollback --project` |
| 生成/结果 | `publish-generation-plan --project --ai-skill --call-budget`; `approve --project --gate generation-authorization`; `prepare-deck-job --project --ai-skill`; `admit-image-call --project --job --slide --attempt --request-ordinal`; `record-image-result --project --job --result --route-report`; `prepare-page-regeneration-job --project --request`; `generation-status --project` |
| 可编辑页 | `convert-page --project --slide --ai-skill --editable-skill`; `promote-editable --project --slide --revision --element --kind`; `plan-edit --input`; `apply-edit --project --slide --revision --input`; `render-editable --project --slide --revision --record-sha256`; `confirm-preview --project --slide --revision --record-sha256 --render [--decision]`; `replace-slide --project --slide --revision --record-sha256` |
| 候选版/交付 | `assemble-candidate --project`; `publish-deck-review --project --candidate-id`; `deck-review-action --project --candidate-id --descriptor-sha256 --action <edit-page\|return-upstream\|confirm-delivery> [--slide-id]`; `acceptance --project`; `acceptance-smoke-copy --project`; `acceptance-record --project --input` |

`record-image-result` 只接收与 immutable job 和已准入 tuple 完全一致的私有 result，并验证串行黏性 route-report。QA 必须覆盖 required text、风格一致性、层级、内容细节和禁用项。页面重生 request、result、route-report 和 edit-plan 均用 `0600` 私有文件。

`deck-review` 不得用通用 `approve`，也没有独立 promotion 命令。`edit-page` 必须且只能携带一个 `--slide-id`；其他 action 禁止携带。只有 `confirm-delivery` 同时认证当前 descriptor 并提升交付。

## WPS/PowerPoint 受控 smoke

先运行 `npm run cli -- acceptance-smoke-copy --project <root>`，只打开返回 `copy.path` 的受控 `deck-smoke.pptx`。选定并记录一个具体文字/对象，临时修改并记录观察到的变化，撤销并记录结果，选择 discard/no-save（不保存）并记录丢弃结果，关闭、重开，确认并记录原内容恢复结果。绝不打开或保存 canonical `output/revisions/<n>/deck.pptx`，也不要求保存 smoke 修改。

将选定对象、观察到的修改、撤销结果、丢弃结果、重开结果及 descriptor path 写入 `0600` 私有输入，再运行 `npm run cli -- acceptance-record --project <root> --input <file>`。输入不得自报 descriptor/source SHA；若真实客户端控制不可用，明确标记验收待完成。
