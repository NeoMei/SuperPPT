# 工作区契约

- 根目录必须包含 `appId: "superppt"` 的 `.superppt-project.json`。每次写入前验证规范路径、所有权、非符号链接和普通文件边界。
- `superppt.json` 是当前状态权威；页面 UUID 不因排序改变。Artifact 使用项目内相对路径、SHA-256 和 revision ID。
- 新项目先把原始输入字节保存到 `source/original.md`。Agent orchestration 依据它撰写严格 schema 的 `brief.json`、`outline.json` 和 `slides/<uuid>/spec.json`；`validate-plan` 只校验/发布视图，不代替语义撰写。
- 不得在已确认 artifact 上先写后补影响分析。上游修改先绑定不可变 impact 证据并确认，再保存 `revisions/<revision-id>/superppt.json` 快照、建立新版本、重写受影响规划 artifact 并重新校验。快照不可覆盖。
- 新导出只在有所有权标记的 staging 中生成；同源和哈希校验通过后才提升为 `output/revisions/<n>/`。失败证据保留，前一个成功版本不变。
- Rollback 只读不可变快照，先保存当前快照再恢复目标，不删除后来产生的文件。
