# 修改路由

## 上游规划修改

修改 brief、outline、页面 spec 或 style 之前，把请求映射到当前 deterministic CLI 支持的 change kind：`brief`、`outline-order`、`outline-structure` + 已有稳定 slide IDs、`slide-spec` + IDs，或 `style`。

1. 用私有 JSON 文件调用 `impact --project <root> --change <file>`；这一步只计划，不修改项目。
2. 展示返回的受影响 IDs、导出失效范围、恢复阶段和 plan SHA，在 `revision-impact` 等待。
3. 确认后依次调用 `approve-impact --project <root> --sha256 <plan-sha>` 和 `apply-impact --project <root>`。
4. 在新版本中由 Agent 编排重写受影响规划 artifact。V1 先 `validate-outline` 并重新确认 `outline`，再补齐 specs、运行 `validate-plan` 并确认 `slide-specs`，最后重新生成/发布样张并确认 `style-sample`。当前实现每次 revision 都重开这三道普通门禁，不能声称只重开受影响门禁。仅排序改变可复用未变页渲染。

当请求无法由这些 deterministic CLI change kind 表达，或当前 CLI 缺少所需校验/提交路由时，立即停止，保留当前项目，报告未支持的变更和需要的产品能力。禁止静默直改 JSON、伪造 gate，或编造 `revise`/`update-outline` 等不存在的命令。

## 单页修改分类

| 用户修改目标 | 默认路由 | 可执行操作 |
|---|---|---|
| manifest 中已提取文字 | editable | `replace-text`、`set-text-style` |
| manifest 中已提取透明素材 | editable | `move-asset`、`replace-asset` |
| 只要求已提取文字/透明素材变成可编辑，不修改内容 | editable | `promote-editable` |
| manifest 中不存在的文字/对象 | regenerate | 修订 spec 和提示词后定向重生该页 |
| 主插画、人物、场景 | regenerate | 修订视觉主体后定向重生 |
| 背景、整体构图、信息布局 | regenerate | 修订构图后定向重生 |
| 当前页已是 editable | editable | 在当前 authenticated modified manifest 上继续编辑 |

背景图中保留的对象不算可编辑对象；不能把整页图片描述为可编辑。路由不确定时选 `regenerate` 并说明原因。

首次 editable 路由执行 `convert-page`。如果用户明确不修改内容，只把已提取目标变成可编辑对象，调用 `promote-editable --project <root> --slide <id> --revision <conversion-id> --element <manifest-element-id> --kind <text|asset>`。`promote-editable` 是页面级重建：`--element` 和 `--kind` 只证明用户所需目标已提取且类型正确，不表示只提升该对象；选中页全部可靠提取的 `text` 和 `transparent assets` 都进入 editable 层，背景和未提取对象仍不可编辑。该路由生成内容不变的 immutable modified candidate，不伪造同文替换，不放宽非空 edit-plan 约束。标题或对象未被提取、ID 不存在或 kind 不匹配时，CLI 以成功分类决策返回单行 `{ "route": "regenerate" }`，不得创建 staging candidate，也不得把 element ID 或用户内容写入输出。这一分类不会跳过后续流程：regenerate 或成功 promote 后仍需 preview/confirm/replace。

如果用户要修改内容，用私有 edit-plan 调用 `plan-edit`/`apply-edit`。两条路径后续都必须执行 `render-editable`，展示 deterministic preview，在 `slide-preview` 得到决定：

- 拒绝：`confirm-preview --decision rejected`，不调用 `replace-slide`；只承诺当前项目和 deck 不变，若命令没有持久化拒绝记录，不声称已有审计证据。
- 通过：先 `confirm-preview`，再以相同 record SHA 调用 `replace-slide`；该命令内部完成整套输出重组，不再额外调用 `assemble`。
- 已是 editable 的当前页：从当前 modified manifest 创建新 edit-plan，不重复调用 `convert-page`，也不重复 OCR 或 vision。
