# 门禁清单

`阶段契约.json` 是可机读权威。它的八个 stage entry 全部是强制用户等待点：Agent 必须停止，展示该 entry 的 `userVisibleArtifact`，并等待用户选择其中一个 `allowedNextActions`。Schema、文件、哈希或机器 QA 通过都不能自动进入下一阶段，也不能推断用户同意。一次只呈现一个内容相关问题或一个决定集，附上已知内容摘要。

## 正常制作顺序

| 决定 | 必须展示 | 可继续到 |
|---|---|---|
| `outline` | 完整页序、稳定 ID、标题、角色、目的、来源覆盖 | 通过后才撰写逐页描述；修改或返回 intake |
| `slide-specs` | 每页核心信息、精确文字、主体、构图/关系、来源证据、禁用项 | 通过后才选择风格；修改某页或返回大纲 |
| 风格单选 | `assets/styles/catalog.json` 中通常三种内容相关风格的真实预览紧凑网格与高信息配方提示 | 只接受一个选择；其余风格按需展开 |
| `style-sample-generation` | 代表页、精确提示词、全部参考图及用途、一次调用、输出位置、宿主将调用 `ai-image-to-ppt` | 一次性样页执行授权；或返回风格/逐页描述 |
| `style-sample` | 实际生成的代表页、仍待批准的 provisional Style Lock、真实调用结果 | 通过后把 authenticated sample 绑定为 non-null approved sample 并提升 Style Lock；或修改风格/代表页 |
| `generation-authorization` | 全部出站提示词、参考图及用途、页数/调用预算、输出位置、宿主调用说明 | 一次性整套执行授权；或返回样页/规划 |
| `deck-review` | `current-deck-link` 返回的唯一完整本地 PPTX 链接、SHA-256、逐页 QA 和人工复核对象标签 | 必须停下，且只能选择 `修改某页 / 返回前序 / 确认交付` |

`style-sample-generation` 与 `generation-authorization` 只允许进入可能花费图像调用的路径；它们本身不能代替每次 `admit-image-call` 的一次性准入。样页确认与样页调用授权是两个不同决定，整套授权也不能由样页确认推断。

`deck-review` 不能用通用 `approve`。只有与当前完整 PPTX revision 和 SHA-256 绑定的 `confirm-delivery` 才能提升正式交付；不得展示第二个交接物。

## 条件决定

- `revision-impact`：展示 immutable impact plan 的受影响稳定 ID、仅下游失效范围、恢复阶段和 SHA。确认后才 `approve-impact` → `apply-impact`；拒绝保留当前版本。
- 页面修改：先用一句话解释 route。手动模式在唯一完整本地 PPTX 链接后停止，等精确 `已保存并关闭`；Agent 模式在同类链接和候选 SHA-256 后停止，等精确 `确认` 并绑定该 hash。拒绝保持 current 不变。

用户始终可以返回前序。先解释变更影响并发布证据，只失效 impact plan 指定的下游页面/导出，从 `restartStage` 指向的第一道变化门禁恢复；不得强制全流程重启或把历史确认当作永久锁定。

Schema 校验、页面 QA、同源/哈希校验是机器边界，不替用户做决定，也不新增虚构门禁。

## 精确下游失效顺序

以下顺序与 `阶段契约.json` 的 `invalidationDependencies` 必须逐项一致：

- `outline` → `slide-specs` → `style-sample-generation` → `style-sample` → `generation-authorization` → `deck-review` → formal delivery → acceptance evidence。
- `slide-specs` → `style-sample-generation` → `style-sample` → `generation-authorization` → `deck-review` → formal delivery → acceptance evidence。
- `style-sample-generation` → `style-sample` → `generation-authorization` → `deck-review` → formal delivery → acceptance evidence。
- `style-sample` → `generation-authorization` → `deck-review` → formal delivery → acceptance evidence。
- `generation-authorization` → `deck-review` → formal delivery → acceptance evidence。
- `deck-review` → formal delivery → acceptance evidence。
- 已批准的 `revision-impact` → `staleSlideIds` → `restartStage` 及其下游 gates → formal delivery → acceptance evidence；拒绝不失效任何内容。
- 已确认的完整 PPTX candidate → `deck-review` → formal delivery → acceptance evidence；拒绝保持 current 完整 PPTX 不变。
